# Issue #196:role_search 支持中文检索(中英同义词表)

> 三问:① 可拆 = 否(一个模块 + 一个测试文件);② 值得第二视角 = 是(同义词表是数据,写漏/写错会让中文检索静默失灵);③ 可并行 = 否。
>
> 分级:**standard**(改动小,但同义词表是长期维护的数据契约)。

## 背景

`role_search` 上线后实测:`role_search("安全")` 返回 `No role matched`。原因不是 bug,是数据——线上 133 个 ECC preset 的 `id` 与 `description` **全为英文**(实测 `安全` 在 `ecc-agent-presets/cordis.patch.yml` 中命中 0 次)。

操作者是中文工作语言(本仓 README 自述),按纪律文本「不确定角色 id 就先 `role_search`」发中文查询会直接落空。

顺带修一处**注释与事实不符**:`roles.mjs` 的 `selectRoles` 文档注释原写「so "安全" and "WCAG planner" both behave」,而「安全」实际零命中(#195 轴2 已指出该处措辞不实)。

## 目标

`role_search` 接受中文关键词,映射到英文概念后检索:

- `role_search("安全")` → 命中 security 类角色
- `role_search("无障碍")` → 命中 a11y / accessibility
- `role_search("数据库")` → 命中 database 类
- 中英混用(如「安全 django」)仍按 OR 语义工作

## 边界

- **只加映射层,不改检索算法**:英文查询行为必须完全不变(回归锁)。
- **不改 133 个 preset**:角色数据一行不动,中文能力来自查询侧的映射。
- 不做分词/模糊音/繁简转换——只做「词 → 英文概念」的直接映射,命中不了就如实返回无匹配。
- 同义词表是**数据**,不是逻辑:新增词只改表,不改代码。

## 验收

1. 中文关键词能命中对应英文角色(安全 / 无障碍 / 数据库 / 测试 / 文档 / 性能 等)。
2. **英文查询行为零变化**(同一批英文 query 在改动前后返回完全相同的 id 列表)。
3. 未知中文词 → 仍返回无匹配,不抛错。
4. 中英混用按 OR 语义。
5. 同义词表覆盖的角色类别在真实 133 行名册上**实测有命中**(不是自造 roster)。
6. `pnpm test` + `pnpm verify` 全绿;升版 + CHANGELOG。

## Tickets

1. 同义词表 + 查询展开(红→绿)
2. 真实名册中文检索测试
3. 文档 / 版本

## 变更

1. **同义词表刻意剔除 `ci`**(实现时发现)。「部署」若映射到 `ci`,会命中 133 行里的 **83 行**,该查询等于「几乎全部」,失去检索意义。已只保留 `deploy`/`deployment`/`release`。
2. **新增第 5 条验收(英文零回归)的实测方法**。用 `git stash` 切到 main 跑同一批英文 query,与分支结果 `diff` 比对,确认**逐字相同**。这不只是断言,是真实对照。
3. **补 3 条 review 期发现的测试缺口**。初版对「映射到不存在的词」和「展开时丢掉原始词」都是 **0 红**——只验证了「表里有东西」,没验证「目标真实存在」。已补:每个映射目标必须在真实名册中出现;展开必须保留原始词;同义词键不得为纯 ASCII(否则英文查询会被静默改写)。
4. **替换一条 #195 的过时测试**。`real-roster.test.mjs` 原有「中文查询零命中(已记录边界)」的断言,#196 后该断言变成对现状的错误描述,已改为钉住「中文能命中」。

> 关于 ASCII 直通:它删掉后测试仍全绿(0 红)。核实后确认它是**性能快路径而非正确性边界**——当前表内没有纯 ASCII 键,英文词走完整路径结果等价。已补一条守卫测试:未来若有人加纯 ASCII 键,该测试会红。
