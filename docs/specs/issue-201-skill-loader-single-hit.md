# issue-201: skill_get 单命中返回正文 + 两处注释/词表修正

## 分级

**trivial**。三处独立小改动,同属 `packages/dsh-skill-surface`,一次发布。不裁剪任何阶段:
TDD 照做(先红后绿 + 反向验证),PR + CI + 双轴 review 照做。

理由:虽是小改动,但 (a) 触及公开工具行为(`skill_get` 的返回形状),
(b) 触及 `domains.mjs` 这个被 nudge 复用的词表,(c) 现有 60 条测试对其中一处**零覆盖**
(轴 A 实测:把 `break` 改 `continue` 后 60 条全绿),所以必须有新测试锁行为。

## 背景:为什么是这三处

三轴独立对抗审查(2026-11-13)的结论:原"委派时自动注入技能正文"方案被否,
理由不是做不到(技术全部成立),而是不该做:

- 208 个委派会话的任务文本含「只报告/只读/审查者」;256 个里只有 5 个写过仓库文件
- 98 次 domain 命中里 90 次落在只读审查员身上,落在真干活的人身上 1 个,且那 1 个是假阳性
- 我的对照基线「顶层 26.5%」里 19 次加载有 16 次来自 `dev-flow`——该技能已不在注册表
- 剔除后:顶层 2/49 = 4.1%,委派 8/256 = 3.1%,「子会话不爱加载」这个现象消失

保留下来的是三个**已实证存在**的缺陷。

## 变更 1:query 单命中直接返回正文

**现状**(`index.js:126-139` `listing()`):不论命中几条,一律返回索引列表。
**新增行为**:`query` 非空且过滤后恰好 1 条 → 直接返回该技能正文(走与 `name` 相同路径,
含 `isModelInvocable` 校验、`injectedSkills.add`、`capped()`)。
命中 0 条 / ≥2 条 / 无 query → 行为不变。

**为什么**:模型调一次 `skill_get({query})` 拿到列表后就不再跟进(实测 3 例全部如此)。
单命中返回正文省掉一次往返。

**边界**:`name` 仍然优先;只有未传 `name` 且 `query` 单命中时才走新路径。

## 变更 2:修正 userText 的失真注释

`index.js:206-208` 现注释:「A delegated child gets its task as a relayed agent message」。
实测子会话首步任务消息 `source.kind === 'user'`、**无 `form`**;全库 relay form 从未出现在
子会话首步批次。注释改成与事实一致。**代码不动**——`source.kind === 'user'` 这一支本来就覆盖了它。

## 变更 3:`注入` 从 security.strong 降级,并加歧义排除

`lib/domains.mjs:77`:`strong: ['鉴权', '密钥', '注入']`。
`注入` 在中文里同时指「安全注入」和「(依赖/提示/点名)注入」,实测 49 个含该词的委派任务里
只有 2 个是安全语义。改为:

- `注入` 从 `strong` 移到 `keywords`
- 新增排除:文本中出现 `ctx.inject` / `提示注入` / `prompt 注入` / `点名注入` 时,
  `注入` 不计入安全域信号

**为什么用排除而不是直接删**:`SQL 注入`/`命令注入` 仍是真安全信号,删掉会漏判。

## 验收标准

1. `skill_get({query:X})` 且 X 在 catalog 里恰好命中 1 条 → 返回该技能正文,并记入 injectedSkills
2. 同一调用命中 0 条 → 原「没有匹配的技能」提示
3. 同一调用命中 ≥2 条 → 仍返回列表
4. 不传 query → 仍返回完整列表
5. 传 name → 优先于 query(既有行为不变)
6. `userText` 注释与实际 source 一致
7. 含「点名注入」「ctx.inject」的任务文本不再单独触发安全域
8. 含「SQL 注入」「命令注入」的任务文本仍触发安全域
9. 全部既有 60 条测试仍绿

## 反向验证(每条必须实测变红)
