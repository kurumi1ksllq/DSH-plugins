# spec: 工具管理面板改左侧栏导航(master-detail)(#91)

> 停点2 产物。分级 **standard**。方向由用户在布局对比稿(现状 + A/B/C/D)中选定:方案 A。
> 注:文件最初误挂 #90 名下,PR review 后更正;issue 编号以 #91 为准。

## 1. 目标

`dsh-inventory` 面板从「顶部 6 分段 tab + 单列长页」改为**左侧栏导航布局**:

- 面板主体变为两栏:左侧固定宽度导航栏(rail)+ 右侧主内容列。
- 6 个视图收进 rail,按两组呈现:
  - **概览**:总览、工作区;
  - **配置**:同步、搜索提供方、提示词注入、凭据保险库。
- rail 项带计数(总览 = 插件包+MCP+技能之和;工作区 = 工作区数;4 个配置视图不计数),
  当前视图高亮(`aria-current`),点击切换的仍是现有 `view` 状态,路由行为不变。
- **统计条(插件包/MCP/技能/工作区 4 个数字)保留在主区顶部**,仅总览视图显示(与现状一致)。

## 2. 方案

- `InventoryPanel` 渲染结构:`S.root`(纵向)顶部保留现有 sticky 顶栏(返回/标题/刷新),
  顶栏之下换成横向容器 = `NavRail` + 主列;**滚动收进主列**,rail 常驻不滚。
- `NavRail` 为新组件(图标可选,先纯文字 + 计数),分组标题用现有 caption 层级;
  rail 视觉沿用现有 token(`C.fill`/hairline/反转高亮),不新增设计语言。
- hero(大标题 + 副标题)、搜索、统计条、各 Section、toast/notice 全部原样移入主列,
  逐视图的显示条件(`isLiveView`、`showList` 等)不变。
- 窄屏:**不引入响应式回退**(桌面面板固定尺寸,始终两栏)——用户在停点1 已确认取向;
  若后续面板出现窄尺寸场景再开 issue。

## 3. 边界

- **纯壳层重构**:数据采集、fetch 路由、行操作(开关/装卸/凭据存取/排序/隐藏技能)、
  workspace detail 交互全部不动;`view` 状态枚举不变。
- 不新增依赖;`client.js` 的 inline-style + 单张 stylesheet 机制保持。
- 分段控件(`S.seg` 及 6 个 `segBtn`)随布局替换而删除,样式表对应清理。
- locale 新增词条(rail 分组与提示),中英双语同步补齐。

## 4. 验收

1. rail 渲染两组共 6 项,计数正确,当前项高亮且带 `aria-current`;点击切换视图,
   各视图内容与现状一致(既有 `client.test.mjs` 全部行为断言不改仍绿)。
2. 总览视图主区顶部有统计条;其余视图不显示(与现状一致)。
3. 工作区流程保持:rail「工作区」→ 列表 → 详情,详情页顶栏返回按钮仍回列表,
   期间 rail 高亮保持在「工作区」。
4. 新增测试覆盖:rail 分组与计数、rail 点击切换、工作区详情期间的高亮保持(红→绿)。
5. 版本号随包升级(`0.8.7` → `0.9.0`,界面结构变更);`pnpm test`、`pnpm verify` 全绿。

## 5. tickets

1. **rail 样式与组件 + locale 词条**:`S` 新增 rail 相关样式、`NavRail` 组件、
   中英 locale 词条;先写失败的渲染测试(rail 两组/计数/高亮)再实现。
2. **面板布局切换**:`InventoryPanel` 壳层改为 rail + 主列,滚动收进主列,
   删除分段控件与 `S.seg` 样式;跑全量既有测试确认行为无回归。
3. **收尾**:工作区详情高亮保持的测试;版本号升级;`pnpm test` + `pnpm verify` 四件套全绿。
